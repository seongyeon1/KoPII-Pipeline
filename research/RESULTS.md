# 한국어 설정 탐색과 조직 범주화 실험

실행일: 2026-09-21. 두 실험은 운영 서버 변경 없이 로컬 모델 추론으로 수행했습니다. 기존 고객 문서·직원 명부를 사용하지 않았습니다.

## 실험의 역할

- **E2:** 처음 도입을 검토했던 두 GLiNER 계열 모델의 라벨 표현·임계값·한국어 경계를 검증 자료에서 선택합니다. 학습 가중치는 바꾸지 않습니다.
- **E3:** 가상 조직에서 치환 정책에 따른 검색 품질과 개인 추정 위험을 측정합니다. 정답 이름 구간과 실제 RoBERTa 출력 조건을 구분합니다.

```mermaid
flowchart LR
    D[한국어 문서] --> N[고정 NER 또는 정답 이름 구간]
    N --> P[마스킹 · 문서 가명 · 팀 · 본부 · 센터]
    H[가상 서비스 명부<br/>누락 · 동명이인 · 오래된 소속] --> P
    P --> T[치환된 문서]
    T --> R[동일 BM25 검색기]
    Q[고정 질의와 관련 문서 정답] --> R
    R --> U[Recall@5 · MRR · 추출형 조직 응답]
    T --> A[고정 후보 필터링 공격자]
    K[신원 목록 / 조직 명부 / 직급·과제] --> A
    A --> V[Top-1 성공 · 후보 수 · 추정 실패]
```

## E2: 한국어 설정 탐색

### 데이터와 선택 절차

공개 데이터 revision `660e03a454f7934261be41390744796565550ce2`를 사용했습니다. 개발 자료는 `valid.jsonl`의 원본 대화 L1 **412건**과 고정 시드 해시 순서로 선택한 L4 음성 문서 **200건**, 합계 **612건**입니다. 파생 단문 L1b와 번역·합성 양성 L2/L3는 개발 자료에 넣지 않았습니다. 합성 양성 자료의 템플릿 구성으로 선택 결과가 지배되는 것을 피하고 한국어 대화 조건에 범위를 한정했습니다.

평가는 `test_kdpii.jsonl` **2,006건**과 `test.jsonl` L4 **580건**입니다. **이미 오류 분석에 사용했던 테스트의 재평가**이며, 미사용 외부 테스트에서 확인한 개선이 아닙니다. 학습·선택 개발·KDPII 사이의 정확히 같은 본문과 명시적 원본 대화 ID 중복은 0건입니다. 의미상 유사 문장이나 합성 템플릿의 독립성을 보증하는 검사는 아닙니다. [분할 검사](results/split-audit.json)

각 후보에서 다음 **30개 설정**을 같은 예산으로 비교했습니다.

| 축 | 값 |
|---|---|
| 유형 표현 | 기존 영문 식별자, 설명형 영어, 한국어 |
| 단어 경계 | 원래 분할기, 한글 음절 단위 분할 |
| 임계값 | 0.1 / 0.3 / 0.5 / 0.7 / 0.9 |
| 고정 설정 | 13개 공통 유형, 180문자 창, 48문자 겹침, batch 4, MPS float32 |
| 선택 목표 | 개발 자료 전체의 exact micro F1 최대; 동률이면 recall, 다음은 사전 grid 순서 |

음성 문서에서 잘못 탐지한 구간도 개발 F1의 FP로 포함했습니다. 탐색 범위의 최댓값이 선택되어도 전역 최적 임계값으로 해석하지 않습니다. 음성/양성 구성비가 바뀌면 선택 결과가 달라질 수 있습니다.

한글 음절 분할은 이름 뒤 조사의 경계를 표현하기 위한 **경계 처리 실험**입니다. 형태소 분석이나 같은 자료를 사용한 추가 학습이 아닙니다. 비한글 구간은 각 모델의 원래 분할을 유지합니다. 단어 수와 span 폭의 의미도 달라지므로 경계 표현 가능성 외의 영향까지 포함합니다.

두 설치 버전의 점수 내림차순 greedy decoding을 확인한 뒤, 임계값 0.1의 출력에서 더 높은 임계값 결과를 계산했습니다. 각 라벨/경계 조합마다 개발 문서 12건을 0.3·0.7에서 직접 다시 추론해 구간·유형 일치를 검사했습니다. 후보별 144문서-설정 검사를 통과해야 후속 단계가 진행됩니다. 서로 다른 창의 중복은 같은 구간·유형일 때만 제거합니다.

### 실행 중 발견한 위치 복원 오류

초기 실행은 Fastino 개발 문서 96건을 저장한 뒤 위치 검사에서 중단됐습니다. GLiNER2 2.0.0 전처리기가 문장부호 없는 창 끝에 `.`을 붙이고 그 문자를 포함한 구간을 반환하는 것이 원인이었습니다. 임의의 위치를 자르거나 문서를 제외하지 않고, 추가 마침표를 입력에 명시한 뒤 **그 알려진 문자만** 원문 좌표에서 제외하도록 수정했습니다. 추가 문자만 예측한 구간에는 대응하는 원문 문자가 없어 반환하지 않습니다. 나머지 범위 오류와 표면 문자열 불일치는 계속 실패 처리합니다.

Fastino의 중단된 예측은 재사용하지 않고 모든 개발/평가 조건을 새로 실행했습니다. NVIDIA는 수정되지 않은 분기에서 이미 완료됐으므로 원래 실행 ID와 [어댑터 스냅샷](studies/snapshots/gliner-before-suffix-fix.py.txt)·[실행기 스냅샷](studies/snapshots/runner-before-suffix-fix.py.txt)을 보존했습니다. [집계 결합기](combine_korean_runs.py)가 설정·데이터 동일성과 NVIDIA 분기 및 공통 채점 코드의 불변성을 검사한 뒤 모델별 실행을 연결합니다. 실행 ID를 소급해서 바꾸지 않았습니다. 스냅샷은 출처 추적용이며 새 재현은 수정된 기본 실행기를 사용합니다. 모델 설정 탐색 범위·선택 기준·평가 자료는 바꾸지 않았습니다.

## E3: 가상 조직의 검색 품질과 개인 추정 위험

### 자료와 통제

사전에 고정한 세 시드에서 각각 **120명·16팀·4본부·2센터·240문서**를 생성했습니다. 총 **360개 가상 신원·720문서**이며 세계 간 신원은 연결하지 않습니다. 팀 규모는 2·4·8·16명입니다. 직원별 상·하반기 문서 두 건에 이름, 직급, 과제, 업무 주제와 업무참조 번호를 넣었습니다. 이름은 한국어 음절 조합으로 만들었으며 실제 직원을 가리키지 않습니다.

각 세계에 타 팀 동명이인 2명, 같은 팀 동명이인 2명, 서비스 명부 누락 7명, 오래된 소속 6명, 복수 팀 소속 5명을 포함했습니다. 공격자의 조직 명부는 현재 소속이며 처리 서비스 명부에만 오류를 주었습니다. 실제 조직 개편의 시계열이나 명부 침해 과정을 재현하지 않습니다.

정책은 원문, 전체 마스킹, 문서 단위 가명, 팀, 본부, 센터입니다. 이름만 정답 PII로 주석한 `gold` 조건과 실제 모델이 출력한 **모든 유형**을 처리하는 `roberta` 조건을 분리했습니다. 가명은 문서별 HMAC이며 공격자에게 키나 복원표를 주지 않습니다. 공개 실험 키는 가상 자료 재현용이며 운영 키로 사용할 수 없습니다.

### 검색과 조직 응답

동일한 **문자 bigram BM25**를 모든 정책에 사용했습니다. 팀·본부·센터 + 업무 주제 + 기간 질의와 조직 조건 없는 주제·기간 질의를 고정했습니다. 문서 생성 문장과 질의 문장은 별도로 작성했지만, 주제와 조직 용어를 공유하는 좁은 템플릿 과제입니다. 질문은 모델이나 정책 결과를 보고 선택하지 않았습니다.

팀 질의는 세계별 96·94·95개, 본부 32개, 센터 16개, 조직 없는 통제 질의 8개입니다. 정답은 생성 시 연결한 조직·주제·기간이 일치하는 문서 집합입니다. **Recall@5는 관련 문서 중 상위 5개에 포함된 비율**, MRR은 첫 관련 문서 순위의 역수입니다. `hit_at_5`도 JSON에 별도로 제공합니다. 관련 문서가 5개보다 많으면 Recall@5는 100%에 도달하지 못합니다.

조직 응답은 업무참조 번호로 문서를 검색한 뒤 상위 1건의 공개 조직 마커를 읽는 고정 추출기입니다. 질의에 정답 조직을 넣지 않았습니다. 공개 조직 계층은 참조하지만 직원-조직 연결 명부는 주지 않습니다. 따라서 원문이나 이름 마스킹 문서에 조직명이 없으면 기권합니다. **생성형 LLM QA나 실제 NPU 임베딩 평가가 아닙니다.**

### 개인 추정 공격

공격 함수에는 치환된 문자열과 허용된 배경지식만 전달합니다. 문서 작성자의 ID·정답 소속·정답 이름 구간은 공격 입력이 아니며, 채점 때만 참조합니다.

| 배경지식 | 공격자가 사용하는 정보 |
|---|---|
| 신원 목록만 | 후보 신원·이름만 알며 직원-조직·직급·과제 연결은 모름 |
| 조직 명부 | 현재 신원-조직 연결을 알고 문서에 남은 이름·조직 마커로 후보를 좁힘 |
| 조직 명부 + 직급·과제 | 위 정보에 직급·과제 연결이 추가되며, 문서에 남아 있는 단서만 사용 |

모든 조건은 후보 120명 안에 실제 작성자가 있는 **closed-world 실험**입니다. ‘신원 목록만’도 후보 신원 자체는 아는 설정이므로 배경지식이 전혀 없는 공격자로 표현하지 않습니다. 동점 후보는 세계별 고정 난수 순서에서 한 명을 고릅니다. 이 실제 top-1 성공률과 함께, 동점에서 균등 선택할 때의 **기대 성공률**을 보고합니다. 기대 성공률은 정답이 후보 집합에 있을 때 `1 / 후보 수`, 없으면 0입니다. 빈 후보 집합은 기권이며 후보 수·정답 포함률·기권율을 별도로 보존합니다.

정답 이름 조건에서 마스킹 대비 팀 범주화는 팀 질의 Recall@5를 **16.73% → 81.30%**로 높였지만, 명부·직급·과제 공격의 기대 성공률도 **26.39% → 73.21%**로 높였습니다. 원문보다 개인 추정이 어려워졌다는 것과 마스킹만큼 보호한다는 것은 다른 주장입니다.

검색 이득은 질의의 조직 수준과 연결됩니다. 정답 이름 조건에서 본부 범주화의 본부 질의 Recall@5는 **58.67%**, 센터 범주화의 센터 질의는 **32.40%**였습니다. 팀 명칭만 남긴 정책은 본부·센터 이름을 자동으로 검색 색인에 추가하지 않으므로 상위 조직 질의에서 불리했습니다. 계층 확장 검색을 도입하면 이 결과가 달라질 수 있습니다.

조직 없는 통제 질의는 모든 정책의 MRR이 100%로 포화됐습니다. 이 쉬운 주제 과제에서는 범주화의 일반적 의미 검색 개선을 입증하지 못합니다. 마스킹과 가명 결과가 유사한 것도 단일 문서의 조직 검색·명부 공격만 평가했기 때문이며, 문서 내 인물 구분이나 문서 간 연결 위험의 동등성을 뜻하지 않습니다.

### 탐지와 명부 오류가 남긴 영향

- 단순한 가상 문서에서 이름 720개는 모두 exact 탐지됐습니다. 이름 일반화 성능의 독립 증거로 삼기에는 템플릿과 이름 생성 방식이 제한적입니다.
- 실제 모델은 이름 외에 **직급 609개, 소속 112개, 여권번호 637개**를 출력했습니다. 가상 문서에는 여권번호를 넣지 않았으며, 업무참조 문자열을 여권번호로 오인했습니다. 실제 NER 조건의 직급·과제 단서 감소와 참조 번호 손실이 함께 발생했습니다.
- 팀 정책의 업무참조 기반 검색 top-1 정답 문서율은 정답 이름 조건 **86.11%**, 실제 NER 조건 **11.39%**입니다. 고정 추출기의 팀 응답 정답률은 각각 **74.17%**, **34.17%**입니다. 잘못 검색한 문서에서도 같은 조직을 답할 수 있으므로 응답 정답률만으로 출처 정확성을 주장하지 않습니다.
- 팀 정책은 이름 누락이 없어도 서비스 명부 오류로 **5%의 문서에 잘못된 팀**을 남겼습니다. 그 문서에서 공격자 후보에 정답이 없어 성공률이 낮아지는 현상을 보호 성공으로 해석해서는 안 됩니다. 정상 명부 대상만 보면 정답 이름·팀 정책의 명부·직급·과제 공격 기대 성공률은 84.47%입니다.
- 정답 이름 조건의 팀 정책에서, 명부·직급·과제 공격 기대 성공률은 **2명 팀 90.32%**, **16명 팀 65.84%**였습니다. 특정 소규모 팀 전체의 일반 위험률이 아니라 이 가상 구성에서의 결과입니다.

업무참조 문자열 오인과 추가 유형 치환은 결과를 본 뒤 확인한 **사후 진단**입니다. 이를 근거로 정책이나 합성 템플릿을 바꿔 재선택하지 않았습니다. 이름 외 유형의 주석이 없으므로 직급·소속 출력을 전부 오탐으로 집계하지 않습니다.

## 적용 판단과 논문에서 주장할 범위

팀 범주화는 팀을 묻는 과제에 유용할 수 있지만, 명부·업무정보가 결합될 때 개인 추정 위험을 높일 수 있습니다. 사용 목적에 필요한 조직 수준, 외부에 공개되는 직급·과제, 명부 최신성, 추가 유형 치환의 검색 손실을 함께 검토할 근거를 제공합니다. 자동으로 ‘팀 범주화가 최선’이라는 정책을 선택하지 않습니다. 마스킹된 본문에 접근제어된 조직 메타데이터 검색을 결합하는 대안은 비교하지 않았으므로, 조직명을 본문에 노출해야 검색이 개선된다는 필수성도 입증하지 않습니다.

이번 결과로 주장할 수 있는 것은 **고정된 한국어 설정 탐색의 재평가 결과**와 **가상 조직·고정 검색기·명시적 공격자에서 관측한 상충 관계**입니다. 미사용 한국어 업무 테스트, 실제 NPU 검색, 실제 직원에 대한 공격, LLM 기반 재식별, 같은 자료 추가 학습 비교, 합성 데이터 학습 효과(E1)는 미수행입니다. 실험 설정을 운영 서버에 자동 배포하지 않았습니다.
