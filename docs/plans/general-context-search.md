# 범용 문서 처리·검색 API

2026-09-21. 범위는 Python 라이브러리와 CLI이며 운영 서비스 배포는 포함하지 않는다.

## 구조와 결정

- 가상 조직 목록·질의 템플릿은 기존 `research` 경로에 유지한다.
- `ContextPipeline`은 한 번 탐지한 결과를 마스킹하고, 유형별 `ContextField`에 연결된 Resolver로 임의 속성을 조회한다. 원문이나 출력 마커에서 조직 정답을 추측하지 않는다.
- `AttributeResolver`는 열 이름과 모호성 판정 열을 설정받는다. 기존 `CsvResolver`의 공개 계약은 유지한다.
- `SearchIndex`는 애플리케이션이 제공한 문서 ID 범위와 구조화된 필터를 검색기 호출 전에 적용한다. 검색 결과의 메타데이터 직렬화는 기본 제외한다.
- `Ranker`와 `Embedder` 프로토콜로 검색기·임베딩 공급자를 교체한다. 기본 BM25는 허용 후보 집합 기준의 통계를 사용한다. 과거 연구용 BM25는 변경하지 않는다.
- `prepare`, `search`, `evaluate-search`는 임의 JSONL에 적용한다. 예제는 가상 자료만 포함한다.

## 검증 계약

1. 허용되지 않은 문서는 검색기·원격 임베딩 입력·결과에 들어가지 않는다.
2. 필터 누락·빈 집합·모호성에서 전체 검색으로 폴백하지 않는다.
3. 원문 이름·조회 예외 메시지는 메타데이터와 진단에 복사하지 않는다. 탐지 오류는 성공 결과를 만들지 않는다.
4. 임베딩 순서·개수·차원·유한값을 확인한다. 사용자 공급 검색기도 같은 점수 계약을 따른다.
5. 기본 JSON 결과에 비공개 메타데이터가 없고, 인덱스 파일은 명시적으로 생성하며 덮어쓰지 않는다.
6. 사용자 qrels의 인덱스·접근 범위·정답 일관성을 확인한 뒤 평가한다.
7. 기존 가상 조직 후속 실험의 모든 집계가 동일해야 한다. 리팩터링 결과를 새 품질 측정으로 발표하지 않는다.

## 적용 한계

문서 권한 계산·인증·테넌트별 디렉터리 범위·영속 벡터 DB·배포는 호출 애플리케이션의 책임이다. 여러 인물이 한 문서에 있으면 속성은 문서별 합집합이며 인물별 대응을 보존하지 않는다. 인터페이스가 범용이라는 사실을 다국어 NER 성능이나 모든 속성의 안전성으로 해석하지 않는다.
